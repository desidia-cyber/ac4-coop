# 03 — Mission conversion plan (all 48 story missions)

Source: `A2_mission_matrix.md` (generated by scanning every
`common/event/mission/mXXX.lua` and its `chara/` directory).

---

## 1. Shape of the work

Every mission is a Lua file plus a set of per-mission includes and character scripts:

```
common/event/mission/mXXX.lua                        mission event logic
common/event/mission/chara/mXXX_player.lua           the player character script
common/event/mission/chara/mXXX_<name>.lua           ally / enemy AC / vehicle / boss scripts
common/event/include/mXXX/constvalue.lua             tuning constants
common/event/include/mXXX/constvalue_hard.lua        hard-mode overrides
common/event/include/mXXX/entityid.lua               mission-local entity ids
common/event/include/mXXX/eventgroup.lua             event group ids
common/event/include/mXXX/pointid.lua                trigger points
```

Because everything is addressed by explicit entity id, **most of the conversion is mechanical**: the
same handful of edits applied to each mission, plus per-mission judgement for scripted sequences.

## 2. The standard change template

Apply to every mission (numbers are measured across the 48):

| # | change | occurrences |
|---|---|---|
| 1 | `ON_DEAD_ENTITY(eo, ENTITY_ID__PLAYER, "OnDeadPlayer")` → `OnPlayerAllDestroyed(eo, "OnDeadPlayer")` | **48 / 48 missions** |
| 2 | `ObserveMissionRegionOut` / `ObserveRegionOut` / `ObserveMissionRegionTimeout` bound to `ENTITY_ID__PLAYER` → per-player variant (§3 of doc 02) | 44 missions (4 have none) |
| 3 | `GetApRateOfAC(ENTITY_ID__PLAYER)` → average across present players | 13 missions |
| 4 | Spawn / mark P2's AC, set `SetTutorialInputMode(USERINPUT)` for it | 48 |
| 5 | Review scripted camera calls for the second viewpoint | 10 missions |
| 6 | Add P2's per-player enemy groups (balancing, see doc 04) | 48, optional per mission |

### The death-handler edit is the single highest-value change

All 48 missions currently fail the instant entity 1000 dies. Changing that one registration is what
turns "co-op" from a toy into a campaign mode, and it is the same edit everywhere.

## 3. Effort tiers

Tiered by measured complexity (`size`, message count, group count, camera calls, difficulty branches):

### Tier A — trivial (10 missions): `m710`–`m719`

~2 KB each, no messages, no AP logic, one group or fewer. These look like short simulator/arena/tutorial
variants. The standard template alone should suffice.

### Tier B — mechanical (22 missions)

Everything else that has no scripted camera and no AP logic:
`m010, m040, m070, m100, m110, m120, m130, m140, m150, m160, m180, m190*, m220, m230, m240*, m250,
m260, m270*, m290, m300, m330, m350, m360, m390`
(* = has either camera or AP calls; treat as B+ and review that one aspect.)

Characteristics: linear objectives, few dialogue triggers, group usage already present in several
(`m010` 35, `m180` 26, `m260` 28), so per-player groups drop straight in.

### Tier C — needs judgement (16 missions)

| mission | why |
|---|---|
| `m000` | 5 chara scripts, ally (Joshua) present, 6 camera calls, AP (2). **Best prototype mission.** |
| `m020` | 12 camera calls, 5 region observers — heaviest scripted-camera mission |
| `m030`, `m050`, `m170`, `m090` | ally AC scripts (`joshua`, `white_ac`) plus AP logic; `m050` has 11 AP calls |
| `m080`, `m200`, `m210`, `m280`, `m380` | heavy AP logic (4–6 calls) — result ranking must be averaged |
| `m240`, `m270`, `m320` | 6 camera calls each; `m320` also 79 group operations and 27 messages |
| `m490` | **2 death handlers** and boss/genius scripts; the finale |

### Special-case categories to review manually

- **Duels against a single enemy AC** (missions with an `_ac`/`_ene_ac` script and few other entities):
  adding a second player changes the fight fundamentally. Consider per-player enemy groups (doc 04)
  rather than simply letting two players dogpile one AC.
- **Escort/defence** (e.g. `m290` carrier/cruiser/head_ship, `m180` submarine/tanker): the protected
  object must survive; two players usually make these easier, not harder — likely needs extra
  attackers rather than more HP.
- **Scripted-camera set pieces** (`m020`, `m320`, `m000`, `m240`, `m270`): a second viewpoint during a
  cinematic can look broken. Plan to force a single view during scripted camera sequences.
- **Timed missions** (region timeout observers): the timeout must be judged for the group, not per
  player, or one slow player ends the run.

## 4. Recommended build order

1. **`m000`** — has an ally AC, is early, and exercises camera + AP + death. Prototype everything here.
2. **`m710`–`m719`** — prove the template applies cleanly at scale with minimal risk.
3. **Tier B sweep** — apply the standard template, then play-test in batches.
4. **Tier C**, hardest last (`m490`).

## 5. Per-mission data

The full table (size, death/region/AP/camera/message counts, difficulty branches, group usage,
character scripts, and which ally/enemy AC scripts exist) is in **`A2_mission_matrix.md`**. Read it
alongside this document when planning a conversion pass.

## 6. What is *not* in the mission scripts

Deferred to the architecture document (`05_ONLINE_LAN_ARCHITECTURE.md`) but worth stating here so it
is not forgotten when estimating mission work:

- the second **camera/viewpoint** and **HUD** are not mission-script concerns;
- **save/progression** for two players is not mission-script;
- **networking** is not mission-script.

Mission conversion is the *content* pass. The *systems* pass is separate and larger for online play.
