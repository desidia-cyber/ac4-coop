# AC4 Lua binding map (BLUS30027)

Static facts only, from the decrypted `EBOOT.elf`. Generated by `tools/re/luamap.py`
(re-runnable); machine-readable form in `research/lua_bindings.tsv`.

## Registration mechanism

**(A) stock Lua 5.0.2 `luaL_reg`** - 8-byte `{ const char *name; lua_CFunction fn; }`
records, NULL-name terminated, `fn` = pointer to an 8-byte PPC64 OPD `{code, toc}`.
9 tables / 113 entries cover the whole standard library (coroutine, _G, debug, io,
os, file-handle methods, math, string, table).

```
; luaL_reg table @101193e4  (name ptr, then OPD ptr -> {code, toc})
101193e4  10010290 "abs"        00e5a9b0 -> code 002bc21c
101193ec  10010298 "sin"        00e5a9b8 -> code 002bc264
101193f4  100102a0 "cos"        00e5a9c0 -> code 002bc2b4
101193fc  100102a8 "tan"        00e5a9c8 -> code 002bc304
10119404  100102b0 "asin"       00e5a9d0 -> code 002bc350
101194a4  00000000             ; NULL name terminates
```

**(B) Dantelion DLLua reflection descriptors** - per-class method arrays whose records
carry an ASCII *and* a UTF-16 name plus 1..4 trailing words; one word points at a run of
up to 7 OPD pointers. Every game-specific command (`eventOperation:*`, `aicontext:*`,
AI operation factories) reaches C++ this way - names are string-compared against these
descriptors, not registered via `luaL_reg`. `runtime_object` is a .bss word (zero in file).

```
; Dantelion descriptor table @00ef6690  {ascii, utf16, runtime_obj, method_set}
00ef6690  100716f8 "CreatePA"    10071950 utf16  15ca11c4 obj  10143348 method_set
          method_set -> 00a80b70 00a78810 00a78b58 00a76a9c 00a76ea8 00a76ef8 00a76c00
00ef66a4  10071708 "SetCapEvent"  10071968 utf16  15ca11b8 obj  10143370 method_set
          method_set -> 00a7d018 00a7881c 00a78b2c 00a76a94 00a76ff0 00a770ec 00a76bac
```

- 1656 distinct names are called by the extracted scripts; 5256 distinct names are defined
  by the scripts themselves (so not engine bindings).

  `debug_out`, `LoadEventStdScriptFile`, `Complete`, `OperationExecuteScheduler`, `AddCandidacy`, `CreateAlwaysTrue`, `AddQueue`, `ShootDesc`, `AddRootOperation`, `AddInitialOperationLayerMT`

## NOT DETERMINED

- `n_args`/`arg_types`/`returns` for mechanism-(B) bindings. They are plain C++ methods
  (`slot[0]` of the OPD set) called by a generic reflection dispatcher, so they never
  touch `lua_tonumber`/`luaL_checknumber` and no arity is encoded statically. The
  descriptor's constant-returning slot[3] was checked against 11 script call sites and
  does not correlate with argument count, so it is not arity.
- Code addresses for the 120-entry mission-command metadata table at `0x00eff1e8`
  (this is where `SetEventPropertyGroup`, `KillEntity`, `GetEventGroupAlives`,
  `SetMissionResult`, `GetApRateOfAC` etc. live). Its records have no OPD pointer;
  their trailing word (`0x15cef4xx`) is past the declared .bss end (`0x15ce2dd8`) and
  never materialised by any instruction, so the implementing functions stay unknown.
- Meaning of OPD-set slots 1..6 (7 slots + 3-NULL terminator is **verified**).
